# The supplied 3x4x4 V map and a three-for-two counterexample

The supplied `3x4x4_m38_cr133_cn194_ZT_reduced_V.sms` map has a verified
**41-addition/subtraction** program in its original signed coordinates.
Its source comment reports 43; the 43-gate source program was not supplied.
Only this 38-by-16 V factor was supplied, so this is not a complete multiplication
tensor certificate. All 608 matrix coefficients replay exactly, without basis
conversion, unary negations, nonunit scalar operations or dead gates.

[Literal program and standalone verifier](../certificates/map_3x4x4_V41_20261017/README.md).

## What produced 41

Andrey Perminov's unchanged LEO solver found 41 directly from scratch, before
our pooling. The external API was pinned at
`7c8b59864e000bdc880938428d8a1991ec1f0bea`, using the existing published
vector-target driver, one native CPU worker, `ignoreUnusedInBound=true`,
coefficient magnitude cap 1, and 0.25 seconds per draw. These settings are
explicit API choices, not a reproduction of current CLI defaults.

The scratch run used base seed 1719344. Draw 5 (seed 1719348) first returned 41.
Its cumulative native sampling/solve time was about 0.0222 seconds; this excludes
compilation, process startup, export and independent verification, so it is not
an end-to-end timing claim. The 20-second scratch run produced 4,429 exact
completions. Optional-hint restarts with exactly two omissions, exactly three,
and uniformly one through eight produced another 30,000 exact completions.
They retained 41. These three arms stopped at 10,000 draws before their nominal
20/20/40-second budgets; actual native times were 12.145, 13.699, 14.278 seconds.
All 34,429 completed raw circuits were checked locally against the original map.

The compact public study retains the first 41 raw witness, 64 selected donors,
and the full audit summary, rather than every redundant completion.

## Additional attempts

A 20-second pool search allowed every signed subset of a target row; it reached
41 from a 49-gate normalized elementary start. A 30-second search also admitted
every signed two-input sum/difference and 64 native donors; it remained 41.
These pools have 179/390 forms and 1,715/10,126 exact binary productions.
All allowed helper computations remain charged; no new forms are free inputs.
The generic generator and frozen pools are published.

A full acyclic finite-pool CP-SAT model reported OPTIMAL 41 for the 179-form pool
in 0.131 seconds, and its selected 41-gate DAG was independently replayed. This
is a solver-reported optimum in that particular dictionary. It is neither an
unrestricted SLP lower bound nor a separately checked infeasibility proof.
The larger 390-form model stopped at its 110.007-second cap with a feasible
41 and a weak solver bound of 30, so it has no optimality conclusion.

A separate transpose experiment gave its scratch and vector arms 10/20 seconds.
It retained 63 additions in the transposed map and 41 after a fully paid return.
Neither pooling nor transpose search improved on Perminov's direct 41.

## Why three-for-two need not split into pair improvements

A joint replacement only needs the final circuit to work. Two improving pair
moves would each require a valid intermediate circuit. That extra condition
can fail: the two new forms may be useful only together.

[The small four-input example](../methods/linear/reconstruction/followup_344_20261017/three_for_two/README.md)
has a seven-addition circuit with helpers p,q,r. Replacing them jointly with u,v
produces the same four outputs using six additions. Yet none of the three
old-helper pairs can be replaced by one helper, even allowing any integer
form constructible by one addition/subtraction from the currently reachable
forms. The verifier exhausts 34,34,36 genuinely new candidate forms for those
three pairs, including doubling, and finds no valid repair.

This disproves the proposed general reduction to two strictly improving pair
moves. It does not rule out equal-cost or temporarily larger intermediate
circuits. In particular, inserting both new helpers before deleting the old
ones is allowed in a larger-neighborhood search.
